# Concurrent team redesign integration

While this release was being tested, the team repository advanced to `b186ce335be71371b4a446191ee5bb340c86196e` (five commits covering security, roles, bookings, discovery and UI). The completed release incorporates that history and preserves its supporting documents, seeds, helpers and tests.

The requested cinematic dark interface remains the active UI. The newer team behaviour is retained: draft/submission, a distinct creator `cancelled` status, social links, all team categories, today/weekend filters, low-data discovery, and the existing poster references. Creator/assigned-staff admission is separate from administrator moderation. Material public event edits still trigger reapproval as part of this release's security controls.

`original_capacity` is frozen when an event is created. Automatic waiting-list promotions increment `refill_count` and stop at `max(1, floor(original_capacity / 10))`. Raising capacity does not reset that budget. Cancellation still releases the booking when the budget is exhausted, and a free place can be booked directly. Total capacity remains bounded at 100,000; the 10% rule applies to automatic promotions, not to capacity increases. Event-first transactional locks, active-account checks and private notifications are retained.

`tools/migrate.php` handles both the earlier schema and the newer redesign schema. It converts the category enum to the expanded literal category list stored as VARCHAR, adds missing release columns, and keeps draft/cancelled status, original capacity, refill counts, social URLs and poster paths. Both upgrade paths are tested twice. Existing `uploads/` posters are served through the controlled media endpoint; direct HTTP access is blocked. Preserve that directory during upgrades alongside `storage/covers/`.

The active application uses `includes/booking.php`, `includes/helpers.php`, `includes/security.php`, `includes/auth.php` and `includes/tickets.php` for its consolidated policies. The earlier team helper modules and their standalone tests are retained for reference/compatibility and are not loaded alongside the active helpers (some declare older versions of the same function names). `tests/security_test.php` forwards to the current security unit suite. Current executable application evidence is in `tests/integration.py`, `tests/browser.cjs`, `tests/security_unit.php`, `tests/role_access_test.php` and `tests/migration.php`; earlier reports are labelled historical. Some retained standalone tests additionally need PDO SQLite.
