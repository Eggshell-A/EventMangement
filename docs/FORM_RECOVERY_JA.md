# フォーム確認エラーのリニューアル

期限切れや不一致のフォームを送信すると、白い画面の `Invalid or expired form` だけでは次の操作が分かりません。共通CSRF検証の拒否画面を、Fairboardの配色に合わせた案内画面へ変更しました。通常のサイトと同じ英語で表示します。

## 利用者への案内

- 「現在のセッションとフォームを照合できなかったため、この送信を停止した」と説明します。期限切れだけが原因とは断定しません。
- 開きっぱなしのページ、別タブでのログイン／ログアウト、Cookie制限、サイトURLの切り替えを、考えられる原因として表示します。
- **新しいページを開く → 内容を再入力 → 確認して一度だけ送信**の順に案内します。
- ログイン失敗時の主ボタンは **Open a new login form**。新しいGETリクエストでログインフォームを開きます。ブラウザーの再読み込みや戻る操作で、古いPOSTを再送させません。
- 再発時の折りたたみヘルプに、Cookieの許可、通常使うサイトURLへの統一、管理者へ知らせる情報を記載します。パスワード・OTP・回復コードを問い合わせ時に渡さないよう案内します。

## デザインの理由

| 選択 | 理由 |
|---|---|
| 既存の暗色背景・コーラル色・Fairboardロゴ | アプリの画面だと認識できるようにする |
| 主操作を目立つボタンで先に表示 | 長い説明を読む前に復帰できるようにする |
| 説明と3ステップを別の領域に配置 | 原因と操作手順を混同させない |
| 穏やかな表現と、今回のリクエストで変更されていない旨の表示 | 利用者を責めず、二重送信への不安を減らす |
| 装飾イラストはスマートフォンで省略 | 小さい画面では操作ボタンを優先する |
| 外部フォント・JSなし、可視フォーカス、ネイティブdetails | 読込失敗やJavaScript無効時にも操作できるようにする |

## 維持するセキュリティ

CSRF不一致は引き続きHTTP **403**。検証・ログ出力・CSP・no-storeを維持し、DBアクセスや変更処理より前に終了します。画面表示にDBや認証済みユーザーのナビゲーションは使いません。

POSTのメール、パスワード、OTP、回復コード、トークン、クエリー文字列、Refererを画面へコピーしません。復帰先は固定のGETページだけで、Hostヘッダーや利用者が送ったURLは採用しません。ボタンは設定済みの`base_url`を使い、IPアドレスと公開URLを混在させた場合も通常のサイトURLへ誘導します。装飾とCSSは現在のアクセス元から読み込み、CSPのself制限を維持します。

| 元の画面 | 安全な復帰先 |
|---|---|
| ログイン、MFAチャレンジ | 新しいログイン画面 |
| パスワード再設定 | 再設定リンクの申請画面（GETだけでは送信しない） |
| アカウント削除 | アカウントの確認画面 |
| adminの更新操作 | admin画面 |
| 予約・取消・QR更新 | 自分の予約一覧 |
| 不明なページ | ホーム |

## 管理者が確認すること

この変更は案内の改善であり、Cookieやデプロイ設定の不一致を自動修正するものではありません。画像のエラー原因は、画像だけでは断定できません。

エラーが毎回出る場合は、ブラウザーで使っているURLと`config.php`の`base_url`、Cookieのpath/domain、`session_secure`を確認してください。HTTPS用のSecure Cookieは通常のHTTPのIPアドレスへ送られません。公開HTTPSリンクとローカルHTTPを混在させず、設定した正規URLで開いてください。HTTPSを終端するプロキシがある場合は、PHP側の`HTTPS`値だけでブラウザー接続を判定しないでください。CSRF検証を無効化して回避しないでください。

今回DB変更はありません。PRをマージ後、コードを更新すれば導入できます。
